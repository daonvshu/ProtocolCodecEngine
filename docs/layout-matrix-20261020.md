# 协议缺省与换序组合验证

日期：2026-10-20。基准仍为提交 `600075a8bf33f3e1d252b2823881875b761ac803`。
本轮只新增离线矩阵及修正文档，没有更改编解码库的执行逻辑。

## 结果

沿用现有 Windows x64、MSVC Release、Qt 5.15.2 配置，
`protocol_decoder_comparison` 编译通过，`--layout-matrix` 退出码为 0：

```text
LAYOUT_MATRIX_RESULT passed layouts=617 partitions=427594 feeds=1334498
```

| 内容长度来源 | 布局数 |
| --- | ---: |
| 前置 S 决定变长 C | 301 |
| C8 固定内容 | 161 |
| 前置 T 对应类型长度表 | 81 |
| 无 C 的纯命令，含保留 S 的变体 | 74 |
| 合计 | 617 |

每种布局覆盖元数据关闭/开启；全部二段、三段切分位置（允许空段），另加逐字节输入及开启日志的逐字节输入。
每次输入后立即检查回调是否恰好对应已经收齐的帧，比较类型、完整内容、元数据以及顺序，
不是只在所有输入完成后统计回调总数。变长 S 场景的第二帧使用空内容，验证长度变化。

额外 388 项测试在首字段为 H 且包含 V 的布局中插入噪声及 CRC 错误帧，
确认拒绝错误帧后仅回调后续正确帧。这些恢复检查不包含在 427,594 个分包用例中。

## 独立预期与原版比较

测试独立按字段顺序组装字节并计算 CRC16，不调用库的编码器生成预期值。
全部布局都核对原版、新版对两个类型的编码字节，并通过独立预期验证新版解码。
CRC 范围包含 V 前的所有字段；E/V 换序时，E 在 V 前才纳入校验。

509 种布局还核对原版整包解码，含元数据开关共 1,018 次检查。
以下 108 种布局仍检查双方编码及新版独立预期，但不在共享进程直接执行原版解码：

| 原版已知缺陷 | 布局数 | 处理 |
| --- | ---: | --- |
| 提取回调字段的循环不访问末节点 | 92 | T 或 C 为末字段时，原版会漏类型或内容；新版必须满足独立预期 |
| 按类型获取长度时向前查找指针不移动 | 16 | T 与 C 间存在 A 时可能死循环；原版由之前的独立超时用例取证 |

这不是把缺陷差异记成两版相同；本轮也未对所有新布局重新执行原版分包差分。
原有 21,988 组差分和 100 MiB 性能结论见 [此前报告](decoder-validation-20261020.md)。
库执行逻辑未改动，因此没有重复跑性能测试。

## 覆盖边界

- H/A/V/E 的缺省组合，S 缺省后的固定长度或类型长度表，无 C 的纯命令。
- 依赖规则允许的 A/T/S/C 排列、E/V 顺序，以及三种内部 H 示例。
- 常规小端一字节数值与大端二字节数值；并非所有字节宽度及混合大小端排列的穷举。
- 不测试缺少 T 的正常接受行为：当前明确要求 T，缺失会调用 `qFatal`。
- 不把重复字段、长度依赖倒置、V 校验尚未编码的后续内容、C8 与 S 混用列为支持项。
- 无 H 的布局验证干净数据的拆包/粘包，不保证遭遇任意干扰后都能唯一恢复帧边界。
- 固定内容长度必须由调用方保证；当前编码器没有强制检查输入长度。

初轮发现测试工具在尾部 S 布局中错误定位 CRC，误改了 S。
辅助代码已改为根据所有前置字段的实际长度定位 V；重新编译并执行整个矩阵后全部通过。
本轮没有为通过测试放宽回调、元数据或恢复断言。

## 复现

使用现有构建树编译 `protocol_decoder_comparison`；运行前将该配置对应的 `<QT_BIN>` 放入 PATH。
在 `<RELEASE_BUILD>/test` 中执行：

```text
protocol_decoder_comparison --layout-matrix
```

完整逐布局结果位于 `comparison-results/layout-matrix.json`，
可移植摘要位于 `validation/decoder-20261020/layout-matrix-summary.json`。
本轮完成后只修正 README 和头文件注释；未部署、未提交。
